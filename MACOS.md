# Запуск на macOS

На маке всё то же самое, что на Windows, только шелл вместо `.bat` и есть
`caffeinate` — мак не уснёт посреди ночного прогона.

## Установка (один раз)

1. Поставь **Google Chrome** — https://www.google.com/chrome/
   (без него откатимся на Chromium, а он палится Яндексом сильнее).
2. Нужен **Python 3.10+**. Системный `python3` в macOS — 3.9, его не хватит:

```bash
brew install python@3.12
```

Нет Homebrew — поставь его (https://brew.sh) или возьми установщик с
https://www.python.org/downloads/macos/

3. Клонируй и поставь:

```bash
cd ~
git clone -b claude/yandex-maps-kz-parser-s39rcl https://github.com/spankyuniverse-lab/YAmap.git
cd YAmap
chmod +x setup_mac.sh
./setup_mac.sh
```

Скрипт сам найдёт самый свежий Python, создаст `.venv`, поставит зависимости,
проверит Chrome и прогонит парсер вхолостую.

## Запуск

### Меню

```bash
./run_gt.sh
```

Спросит режим и сколько браузеров запускать одновременно (Enter = 2).

### Долгий прогон с авто-перезапуском

```bash
./watch_gt.sh --all-cities --category gt-fuel -o kz_azs.xlsx --workers 2 --api-intercept
```

Упал целиком (Chrome умер, вайфай отвалился) — поднимется сам, продолжит с
места обрыва. Это то, что стоит запускать на ночь.

### Командой

```bash
./run.sh --all-cities --category gt-fuel -o kz_azs.xlsx --workers 2 --api-intercept
./run.sh --city Алматы --category gt --api-intercept
./run.sh --doctor
./run.sh --list-cities
```

### Сельский Казахстан: аулы, трассы, вся страна

Города собраны — дальше три уровня охвата глубинки (все переживают Ctrl+C и
продолжаются той же командой):

```bash
# 1. Аулы и сёла — райцентры, аулы, придорожные посёлки (~12-18 ч на 2 браузерах)
./watch_gt.sh --all-cities --cities аулы --category gt-село -o kz_aul.xlsx --workers 2 --api-intercept

# 2. Трассы — коридоры вдоль всех магистралей: придорожные АЗС, кафе, магазины
./watch_gt.sh --routes --category gt-село -o kz_routes.xlsx --workers 2 --api-intercept

# 3. ВСЯ страна сплошной сеткой — финальный пылесос, несколько суток.
#    Сетка обрезана по границе РК (Каспий/РФ/Узбекистан не тратят время).
./watch_gt.sh --country --category gt-село -o kz_country.xlsx --workers 2 --api-intercept
```

`gt-село` — сельский набор рубрик (АЗС, продуктовые, сельпо, кафе, столовые):
гипермаркеты и рестораны в аулах не водятся, а так прогон почти вдвое короче.
Нужны все рубрики — ставь `--category gt`.

### Все сёла из OpenStreetMap (тысячи вместо 415)

Встроенный справочник аулов собран вручную. Все реальные сёла Казахстана
лежат в OpenStreetMap — забираются одной командой, бесплатно и без капчи:

```bash
./run.sh --help >/dev/null            # просто чтобы venv точно был собран
.venv/bin/python fetch_osm_places.py  # выкачает kz_osm_places.json
```

Потом гонишь по ним:

```bash
./watch_gt.sh --all-cities --cities osm --category gt-село \
    -o kz_osm.xlsx --workers 2 --api-intercept
```

Точки вне границы Казахстана отрезаются автоматически.

### Все сёла из Wikidata (данные Википедии)

```bash
.venv/bin/python fetch_wikidata_places.py --countries kz,uz,kg
./watch_gt.sh --all-cities --cities wiki --category gt-село -o wiki.xlsx --workers 2 --api-intercept
```

Можно слить с выгрузкой OSM — источники дополняют друг друга:

```bash
.venv/bin/python fetch_wikidata_places.py --merge kz_osm_places.json
```

### Три страны

По умолчанию собираются все три — Казахстан, Узбекистан, Киргизия. Сузить:

```bash
./run.sh --list-cities                    # что есть по каждой стране
./watch_gt.sh --all-cities --countries uz --category gt -o uz.xlsx --workers 2 --api-intercept
./watch_gt.sh --all-cities --countries kz,kg --category gt-село -o kz_kg.xlsx --workers 2 --api-intercept
```

### Ускорители (по желанию)

```bash
# не печатать в строку поиска, ходить по прямым ссылкам (−1-3 с с запроса)
./watch_gt.sh --all-cities --cities аулы --category gt-село -o kz_aul.xlsx --workers 2 --url-only

# снимать выдачу запросами к внутреннему API вместо прокрутки (кратно быстрее)
./watch_gt.sh --all-cities --cities аулы --category gt-село -o kz_aul.xlsx --workers 2 --fast-api

# сработает ли --fast-api именно у тебя (ничего не собирает, только отчёт)
./run.sh --probe-api --city Алматы "Заправки"
```

Обе опции по умолчанию выключены; если что-то пойдёт не так, парсер сам
вернётся к обычному сбору — данные не потеряются.

### Каждый запуск — своя папка

Выгрузки, части воркеров и прогресс складываются в `runs/<дата_время>__<имя>/`:

```
runs/2026-09-12_21-40__kz_aul/
    kz_aul.xlsx          ← сводная выгрузка
    kz_aul.w1.xlsx       ← части воркеров
    kz_aul.w1.cities.json ← что уже пройдено (докачка)
```

Перезапуск той же командой **продолжает в той же папке** — после Ctrl+C или
падения докачка находит собранное. Нужен чистый старт с нуля, не трогая
прежнее:

```bash
./watch_gt.sh --all-cities --cities аулы --category gt-село -o kz_aul.xlsx --workers 2 --new-run
```

Сторож снимает `--new-run` после первой попытки — иначе каждое падение
начинало бы сбор заново. Свою папку можно назвать руками: `--run-dir runs/ночь`.
Путь с каталогом (`-o выгрузки/kz.xlsx`) парсер не трогает вовсе.

## Чтобы мак не уснул

`run.sh` сам оборачивает прогон в `caffeinate -is` — сон по простою отключается
на время работы и включается обратно после.

Но **закрытая крышка усыпляет мак в любом случае**. На ночь:

- ноутбук в розетке;
- **крышка открыта** (можно притушить яркость в ноль);
- или подключи внешний монитор — тогда можно и закрыть.

## Несколько браузеров

`--workers N` откроет N окон Chrome. Все идут с **одного твоего IP**, Яндекс
считает запросы по нему: **2 — рекомендую**, 3 — на грани, 4+ ускоряет ровно до
момента, когда капча прилетит всем сразу.

Прогресс пишется по ходу, Ctrl+C безопасен, повторный запуск продолжает.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Нужен Python 3.10 или новее` | `brew install python@3.12`, потом заново `./setup_mac.sh` |
| `permission denied: ./run.sh` | `chmod +x *.sh` |
| Chrome не стартует | Закрой все окна Chrome и запусти заново (persistent-профиль занят) |
| Постоянная капча | Выключи VPN — нужен обычный казахстанский IP. И уменьши `--workers` до 1 |
| Мак засыпает | Крышка открыта + питание от сети (см. выше) |
| В выгрузке нет телефонов и координат | Парсер сам напишет об этом в конце прогона. Значит Яндекс отдал выдачу без «богатого» слоя: проверь `./run.sh --probe-api --city Алматы "Заправки"` и пришли `reports/api_unknown_shape.json` — по нему это чинится |
| Прогон начался с нуля, хотя данные были | Смотри, в какую папку он пишет (строка «Продолжаю прогон в папке …» или «Новый прогон — папка …»). Убери `--new-run`, если он остался в команде |
| Всё непонятно | `./run.sh --doctor` — один экран состояния, его можно переслать целиком |

## Где результат

Файлы `.xlsx` кладутся в папку прогона `runs/<дата_время>__<имя>/` (см. «Каждый запуск — своя папка» выше).
Внутри лист «Все результаты» и
отдельный лист на каждый запрос. Логи — в `logs/`, сводки прогонов — в
`reports/`.

Перенести собранное с другой машины (чтобы не пересобирать): скопируй папку
прогона целиком в `runs/` — там уже лежат и `kz_azs.xlsx`, и части
`kz_azs.w*.xlsx`, и прогресс `*.cities.json`. Парсер увидит уже пройденные
города и продолжит с новых.
