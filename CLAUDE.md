# YAmap — парсер Яндекс.Карт (Казахстан, Узбекистан, Киргизия)

Собирает организации (АЗС, продукты, еда и любые рубрики) по городам и аулам
в книгу Excel. Весь код — в `yandex_parser.py`, тесты — в `tests/`.
Общаемся по-русски.

## Где запускать

**Только на маке пользователя, не в облаке.** Сбору нужен обычный
казахстанский IP: с IP датацентра Яндекс сразу даёт капчу, а из облачного
контейнера до yandex.kz вообще нет доступа. Прокси и VPN — тоже нет.

```bash
cd ~/PycharmProjects/yandexmap/YAmap
./setup_mac.sh                   # один раз: окружение .venv и браузер
./run.sh                         # пошаговое меню (без аргументов)
./run_gt.sh                      # быстрое меню GT: 19 городов, аулы, трассы
./run.sh --doctor                # что собрано, ошибки, капчи — один экран
```

## Режимы

| Что нужно | Команда |
|---|---|
| АЗС/продукты по 19 крупным городам КЗ | `./run_gt.sh`, пункт 1 |
| Один город + свои категории | `./run.sh` → пункт 2, или `./run.sh --city Алматы --search АЗС Продукты "Где поесть" --api-intercept` |
| Аулы и сёла | `./run.sh --all-cities --cities аулы --category gt-село -o kz_aul.xlsx -w 2 --api-intercept` |
| Всё подряд (города + аулы) | `--cities макс` |
| Долгий прогон на ночь, сам поднимается после падения | `./watch_gt.sh <те же аргументы>` |

**`--search` и `--category` — не одно и то же.** `--category Продукты`
разворачивает ГРУППУ каталога в восемь запросов («мясные магазины»,
«кулинарии»…). `--search Продукты` шлёт в Яндекс ровно «Продукты». Если
человек показал, что он печатает в поиск, — это `--search`.

## Правила, которые нельзя нарушать

1. **Антикапча священна.** Паузы между запросами, прогрев, «человеческий»
   скролл — это и есть защита от капчи. Не уменьшать их ради скорости.
   `YAMAP_PACING` меньше единицы — ТОЛЬКО для тестов против макета, против
   настоящего Яндекса никогда.
2. **Браузеров: 2 — рекомендую, 3 — на грани.** Все идут с одного IP. Пошла
   капча — уменьшить `--workers` (`-w`), это единственное лечение.
3. **Капчу не обходить.** Если она пошла — остановить, снизить число
   браузеров, подождать, продолжить той же командой.
4. **Не начинать с нуля без нужды.** Повторный запуск той же командой
   продолжает с места обрыва. `--new-run` — только если нужен именно чистый
   прогон.

## Как вести прогон самому (автономно)

- Запускать в фоне, лог писать в файл, проверять раз в 15–30 минут.
- Прогресс виден в строках `[ЧЧ:ММ:СС] всего ~N` и `wN собрано …`.
- Упал воркер — причина печатается сразу под строкой «Воркер N упал»
  с пометкой `wN|`. Целиком — `logs/workerN.log`. Родитель поднимает
  воркера сам (30 → 60 → 90 с), города умершего доберёт в конце.
- «Капч поймано» растёт — снизить число браузеров и перезапустить той же
  командой.
- Мак не должен засыпать: `run.sh` и сам парсер держат `caffeinate`, но
  крышка должна быть открыта и питание — от сети.

## Где результат

`runs/<дата_время>__<имя>/<имя>.xlsx`. Листы книги:

1. **Все результаты** — всё одной таблицей (докачка читает именно его)
2. **Заправки / АЗС**
3. **Продуктовые магазины / Продукты**
4. …остальные рубрики (в GT: Поесть, Супермаркеты, Гипермаркеты — как в 2ГИС)
5. **Крупные города** — 19 городов из `MAJOR_CITY_SHEET`
6. **Аулы и сёла** — всё остальное
7. **Сводка по НП** — сколько чего в каждом пункте, сверху ИТОГО

Листы 5–7 строятся по колонке «НП (по адресу)» (где точка стоит), а не по
«Город (прогон)» (где её нашли): окно карты накрывает соседей.

Зум вьюпорта — 11 (город целиком с пригородами, ~59 км).

## Проверка изменений в коде

```bash
python3 tests/run_all.py         # 25 тестов, ~3 минуты
```

Два прогона тестов в одной папке одновременно не запускать — они портят
друг другу файлы (стоит замок, второй прогон откажется стартовать).
Интернета и Яндекса тесты не требуют: всё идёт против локального макета.
