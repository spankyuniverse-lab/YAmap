# Запуск на Windows

Сборка под Windows: три `.bat` файла, венв ставится сам, браузер идёт **видимым
окном** — на десктопе это лучший анти-детект, который вообще возможен.

## Почему Windows лучше сервера

| | Linux-сервер (headless/Xvfb) | Windows-десктоп |
|---|---|---|
| Браузер | headless-shell или Chrome под Xvfb | настоящий Chrome, настоящее окно |
| WebGL/GPU | SwiftShader/llvmpipe — софт-рендер, палево | настоящая видеокарта |
| IP | датацентр (низкий траст) | домашний/мобильный КЗ (высокий траст) |
| Шрифты, аудио, экран | обрезанный набор | реальные |
| Капча | ловится часто | почти не ловится |

Отсюда правило: **на Windows не включай headless**. Парсер сам это понимает и
стартует с видимым окном; принудительно скрыть — переменная `YAMAP_HEADLESS=1`
(не рекомендуется).

## Установка (один раз)

1. Поставь **Python 3.11+** — https://www.python.org/downloads/
   При установке обязательно галочка **«Add python.exe to PATH»**.
2. Поставь **Google Chrome** — https://www.google.com/chrome/
   (без него откатимся на Chromium, а он палится сильнее).
3. Скачай проект и распакуй, например в `C:\YAmap`.
4. Двойным кликом запусти **`setup_windows.bat`**.

Скрипт создаст `.venv`, поставит зависимости, проверит Chrome и прогонит
парсер вхолостую. В конце должен написать «Готово».

## Запуск

### Меню (проще всего)

Двойной клик по **`run_gt.bat`**:

```
[1] 19 городов КЗ: весь GT
[2] 19 городов КЗ: только АЗС
[3] 19 городов КЗ: только продуктовые
[4] Все города и посёлки (96): весь GT
[5] АУЛЫ И СЁЛА: сельский GT-набор
[6] ТРАССЫ: придорожные АЗС/кафе
[7] ВСЯ страна сплошняком: сельский набор
[8] ВСЯ страна сплошняком: весь GT
[9] Один город
```

После выбора режима спросит, **сколько браузеров запускать одновременно**
(Enter = 2).

### Командой

`run.bat` пробрасывает любые аргументы в парсер:

```bat
run.bat --city Алматы --category gt
run.bat --all-cities --category gt -o kz_gt.xlsx --workers 3
run.bat --all-cities --cities aul --category gt-rural -o kz_aul.xlsx -w 2
run.bat --routes --category gt-rural -o kz_routes.xlsx -w 2
run.bat --country --category gt-rural -o kz_country.xlsx -w 2
run.bat --list-cities
run.bat --list-categories
```

## Несколько браузеров одновременно

`--workers N` запускает N отдельных Chrome — на экране будет N окон, работа
между ними поделена, в конце всё сливается в один файл с дедупликацией.
Пока идёт сбор, в консоли раз в 30 секунд печатается счётчик:

```
   [14:22:05] w1: 812 | w2: 774 | w3: 690  →  всего ~2276
```

**Сколько ставить:** все браузеры выходят с **одного твоего IP**, Яндекс считает
запросы по нему. **2 — рекомендую**, 3 — уже на грани, 4+ ускоряет ровно до
момента, когда капча прилетит сразу всем. Начни с 2; если за час капчи не было,
можно поднять.

Ctrl+C гасит все браузеры сразу, прогресс каждого сохраняется, повторный запуск
той же команды продолжит. Логи по каждому — `logs\worker1.log`, `worker2.log`, …

Или из PowerShell/cmd вручную:

```bat
.venv\Scripts\python.exe yandex_parser.py --all-cities --category gt -o kz_gt.xlsx
```

## Прерывание и докачка

Жать **Ctrl+C** безопасно в любой момент:

- `--all-cities` — прогресс пишется после каждого города в `<файл>.cities.json`,
  частичные выгрузки лежат в `<файл>_parts\`. Повторный запуск **той же команды**
  продолжит с непройденного города.
- `--country` — прогресс по тайлам в `<файл>.progress.json`, тот же принцип.

Компьютер во время сбора можно использовать, но **окно Chrome не закрывай** и
не сворачивай его свёрткой, которая усыпляет вкладку. Спящий режим Windows на
время долгого прогона лучше отключить:
`Параметры → Система → Питание → Спящий режим → Никогда`.

## Режим «само следит, само чинит»

Три уровня присмотра, чтобы прогон не требовал няньки:

1. **Внутри воркера** — капча детектится, троттлинг замедляется, ошибки
   поиска уходят в retry, неудачный «Показать ещё» больше не роняет запрос.
2. **Родитель следит за воркерами** — упавший браузер поднимается сам (до 5 раз,
   с паузой 30/60/90 сек) и продолжает **с места обрыва**, а не с нуля. В строке
   прогресса это видно как `⟳1`. Если воркер так и не поднялся, родитель в конце
   **сам доделывает его города** одним браузером — дыр в выгрузке не остаётся.
3. **Сторож `watch_gt.bat`** — перезапускает весь процесс, если он упал целиком
   (Chrome умер, интернет отвалился, комп ушёл в сон):

```bat
watch_gt.bat
watch_gt.bat --all-cities --category gt-grocery -o kz_grocery.xlsx --workers 2
```

Без аргументов гоняет АЗС по всем городам в 2 браузера. После каждого падения
печатает диагностику и ждёт минуту.

## Диагностика одной командой

```bat
run.bat --doctor
```

Печатает одним экраном: версия Python, найден ли Chrome, что уже собралось и
сколько записей, где остановилась докачка, сколько поймано капч и последние
ошибки из логов. **Этот вывод можно целиком скопировать и прислать** — по нему
видно состояние прогона без пересылки логов.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Python не найден` | Переустановить Python с галочкой «Add to PATH» |
| `Не удалось создать .venv` | Запустить `setup_windows.bat` от имени администратора |
| Постоянная капча | Не сидеть через VPN/прокси — нужен обычный казахстанский IP. Один прогон = один браузер, не запускать несколько параллельно |
| Кракозябры в консоли | Windows Terminal вместо старого `cmd.exe` |
| `Результаты не найдены` | Проверить интернет и что в окне Chrome реально открылись Яндекс.Карты |
| Chrome не стартует | Закрыть все окна Chrome и запустить заново (persistent-профиль занят) |

## Где результат

Файлы `.xlsx` появляются в папке прогона `runs\<дата_время>__<имя>\`. Внутри:

- лист **«Все результаты»** — всё одной таблицей;
- отдельный лист на каждый запрос (АЗС, супермаркет, …).

Логи прогона — в `logs\`, сводка по прогону — в `reports\`.

### Каждый запуск — своя папка

Выгрузки, части воркеров и прогресс складываются в `runs\<дата_время>__<имя>\`:

```
runs\2026-09-12_21-40__kz_aul\
    kz_aul.xlsx          ← сводная выгрузка
    kz_aul.w1.xlsx       ← части воркеров
    kz_aul.w1.cities.json ← что уже пройдено (докачка)
```

Перезапуск той же командой **продолжает в той же папке** — после Ctrl+C или
падения докачка находит собранное. Нужен чистый старт с нуля, не трогая
прежнее:

```bat
watch_gt.bat --all-cities --cities аулы --category gt-село -o kz_aul.xlsx --workers 2 --new-run
```

Сторож снимает `--new-run` после первой попытки — иначе каждое падение
начинало бы сбор заново. Свою папку можно назвать руками: `--run-dir runs\ночь`.
Путь с каталогом (`-o выгрузки\kz.xlsx`) парсер не трогает вовсе.
