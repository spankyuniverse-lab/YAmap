# YAmap — Парсер Яндекс.Карт (Казахстан)

Парсер организаций с **Яндекс.Карт Казахстана (yandex.kz)** с поддержкой
динамической подгрузки (infinite scroll), парсинга по категориям (аналог 2ГИС)
и снятием **всех доступных данных** об организации через внутренний API.

По умолчанию работает с доменом **yandex.kz** и автоматически пинит
гео-вьюпорт Казахстана (`ll=долгота,широта` + `z` + `lang=ru_RU`), чтобы выдача
была казахстанской, а не «уползала» в Москву. Домен переключается флагом
`--tld` (kz/ru/com/by/uz/tr).

## Установка

### Windows

Двойной клик по **`setup_windows.bat`** — поставит венв и зависимости, проверит
Chrome. Дальше **`run_gt.bat`** (меню) или `run.bat <аргументы>`.
Подробности — **[WINDOWS.md](WINDOWS.md)**.

### macOS

```bash
chmod +x setup_mac.sh && ./setup_mac.sh
```

Дальше `./run_gt.sh` (меню), `./watch_gt.sh` (долгий прогон с авто-перезапуском)
или `./run.sh <аргументы>`. Нужен Python 3.10+ (системный 3.9 не подойдёт:
`brew install python@3.12`). Подробности — **[MACOS.md](MACOS.md)**.

### PyCharm

Открой папку проекта — в списке запуска уже лежат готовые конфигурации
(«АЗС — все города», «Продуктовые», «Диагностика», «Меню»). Останется указать
интерпретатор `.venv/bin/python`. Подробности — **[PYCHARM.md](PYCHARM.md)**.

Запуск **без аргументов** (кнопка ▶ на `yandex_parser.py`) открывает пошаговое
меню — вбивать флаги не нужно.

### Linux

```bash
pip install -r requirements.txt
playwright install chrome     # предпочтительно настоящий Chrome (лучший анти-детект)
# если настоящего Chrome нет — сгодится bundled Chromium:
playwright install chromium
```

Если Chrome не установлен, парсер автоматически откатится на bundled Chromium
(с инъекцией stealth-JS). В окружениях без скачанных браузеров Playwright
(CI, docker, песочница) можно явно указать бинарь:

```bash
export YAMAP_BROWSER_PATH=/path/to/chromium   # напр. /opt/pw-browsers/chromium
```

## Использование

### По поисковому запросу

```bash
python yandex_parser.py "кофейни Алматы"
python yandex_parser.py "автосервис Астана" -n 200 -o авто.xlsx
python yandex_parser.py "аптеки Шымкент" --api-intercept        # все поля из API
python yandex_parser.py "рестораны Караганда" --detail
```

### По категориям (аналог 2ГИС)

```bash
# Каталог категорий и список городов KZ
python yandex_parser.py --list-categories
python yandex_parser.py --list-cities

# Все подкатегории группы «еда» (рестораны, кафе, бары, ...)
python yandex_parser.py --city Алматы --category еда

# Конкретные категории
python yandex_parser.py --city Астана --category рестораны кафе бары

# Все категории каталога сразу (полный сбор по городу)
python yandex_parser.py --city Шымкент --all-categories -n 100 --api-intercept
```

### GT-сегмент (АЗС + продуктовая розница) по всем городам

`gt` — готовый пресет General Trade: заправки и продуктовые точки.

| Пресет | Запросы |
|---|---|
| `gt` | АЗС, АГЗС, газовая заправка, продуктовый магазин, супермаркет, минимаркет, гипермаркет, магазин у дома, продуктовый рынок |
| `gt-азс` (`gt-fuel`) | только топливо |
| `gt-магазины` (`gt-grocery`) | только продуктовые |

```bash
# Весь GT по ВСЕМ городам Казахстана в один файл (рекомендуемый режим)
python yandex_parser.py --all-cities --category gt -o kz_gt.xlsx --api-intercept

# Раздельно — так быстрее получить первый результат
python yandex_parser.py --all-cities --category gt-fuel    -o kz_azs.xlsx --api-intercept
python yandex_parser.py --all-cities --category gt-grocery -o kz_grocery.xlsx --api-intercept

# Один город
python yandex_parser.py --city Алматы --category gt --api-intercept
```

`--all-cities` идёт по справочнику городов (`--list-cities`), собирает каждый
своим вьюпортом, дедуплицирует между городами и **пишет общий файл после
каждого города**. Ctrl+C безопасен: прогресс в `<файл>.cities.json`, части —
в `<файл>_parts/`, повторный запуск той же команды продолжит с нужного города.

Нужны ещё и трассы с посёлками — это `--country` (см. ниже), он в разы дольше.

### Несколько браузеров одновременно (`--workers`)

```bash
python yandex_parser.py --all-cities --category gt -o kz_gt.xlsx --workers 3
python yandex_parser.py --country --category gt-fuel -o kz_azs.xlsx -w 2
python yandex_parser.py --city Алматы --category gt -w 2
```

Каждый воркер — отдельный процесс со своим Chrome, своим профилем
(`.browser_profile_wN`), своим файлом (`kz_gt.w1.xlsx`, `.w2`, …) и своим
прогрессом. Родитель режет работу, показывает живой счётчик и в конце сливает
всё в общий файл с дедупликацией:

```
   [14:22:05] w1: 812 | w2: 774 | w3: 690  →  всего ~2276
```

Как режется работа:

| Режим | Что раздаётся воркерам |
|---|---|
| `--all-cities` | города вперемешку (1,2,3,1,2,3…) — миллионники не достаются одному |
| `--country` | тайлы сетки по остатку от деления — покрытие ровно один раз, без пересечений |
| `--city --category` | категории |

**Сколько ставить.** Все воркеры сидят на **одном твоём IP**, и Яндекс считает
запросы именно по нему. 2–3 — рабочий режим. 4+ ускоряет линейно ровно до
момента, когда прилетит капча сразу всем. Потолок — 8, но это не рекомендация.
Ctrl+C гасит всех, прогресс каждого сохраняется, повторный запуск продолжает.

Логи воркеров — `logs/worker1.log`, `logs/worker2.log`, …

### Максимальный охват (больше результатов + защита от капчи)

Яндекс отдаёт ограниченное число организаций на один вид карты. Чтобы собрать
как можно больше по городу — **grid-свип** (сетка вьюпортов) + cooldown:

```bash
python yandex_parser.py --city Алматы --category АЗС \
    --api-intercept --grid 3 --cooldown-every 5 --no-headless
```

`--grid 3` пройдёт 9 вьюпортов по площади Алматы и объединит результаты
(дубли отсекаются автоматически).

Результат по категориям сохраняется в Excel:
- **Лист «Все результаты»** — сводная таблица с колонкой «Поисковый запрос»
- **Отдельный лист на каждую категорию** (рестораны, кафе, бары, …)

### Выбор домена и гео-привязка

```bash
# Другой домен
python yandex_parser.py "аптеки Ташкент" --tld uz

# Явный центр карты (долгота,широта) и зум — если города нет в пресетах
python yandex_parser.py "кафе" --ll 76.8897,43.2389 --z 13
```

## Параметры

| Параметр | Описание |
|---|---|
| `query` | Поисковый запрос (режим одиночного поиска) |
| `--tld` | Домен: `kz` (по умолчанию), `ru`, `com`, `by`, `uz`, `tr` |
| `--city` | Город для парсинга по категориям (для KZ пинит вьюпорт) |
| `--ll` | Центр карты `долгота,широта` для гео-привязки |
| `--z` | Зум карты (11-13 город, 10 пригороды, 14 центр; по умолч. 12) |
| `--category` | Категории, группы (еда, авто, …) или пресеты сегментов (`gt`, `gt-fuel`, `gt-grocery`) |
| `--all-categories` | Парсить все категории из каталога |
| `--all-cities` | Прогнать `--category` по **всем городам КЗ** и слить в один файл (докачка после Ctrl+C) |
| `--country` | Сплошной свип по **всей территории** КЗ: города, посёлки, трассы (долго) |
| `--step` | Шаг национальной сетки, град. (меньше = плотнее и дольше) |
| `-w, --workers N` | **N браузеров одновременно** (см. ниже). Работа режется по городам / тайлам / категориям |
| `--list-categories` | Показать каталог категорий и выйти |
| `--list-cities` | Показать все 96 городов Казахстана с координатами |
| `--doctor` | Диагностика одним экраном: что собралось, докачка, капчи, ошибки |
| `-n, --max-results` | Максимум организаций на запрос/категорию (по умолч. 5000; для `--country` — 250 на тайл; `0` = без лимита) |
| `-o, --output` | Файл: `.xlsx`, `.csv` или `.json` |
| `--api-intercept` | Перехват JSON из внутреннего API (надёжнее DOM, **все поля**) |
| `--grid N` | Grid-свип N×N вьюпортов по площади города — **кратно больше результатов** (напр. `--grid 3` = 9 видов). По умолч. 1 (выкл) |
| `--cooldown-every N` | Профилактическая пауза каждые N категорий (против капчи на объёме) |
| `--cooldown-sec S` | Длительность cooldown-паузы, сек (по умолч. 90) |
| `--detail` | Открывать карточку каждой организации для телефона/сайта (медленно) |
| `--no-headless` | Показывать браузер (рекомендуется для решения капчи) |
| `--proxy` / `--proxy-file` | Прокси / файл со списком прокси (ротация) |
| `--resume` | Продолжить прерванный сбор из файла результатов |
| `--config` | Конфиг-файл (YAML/JSON) |
| `--scroll-pause` | Пауза между прокрутками, сек (по умолч. 1.0) |
| `--detect-selectors` | Автодетект CSS-селекторов на живой странице |
| `--show-selectors` / `--reset-selectors` | Показать / сбросить кеш селекторов |

## Собираемые данные («снять все данные»)

Модель содержит **60 полей**. Наиболее полно они наполняются в режиме
`--api-intercept` (перехват внутреннего API), где Яндекс отдаёт JSON с богатой
карточкой организации:

- **Идентификаторы:** ID организации (permalink), slug, URI, гео-ID
- **Названия:** название, короткое название, юр. лицо
- **Адрес:** короткий и полный адрес, страна, регион, город, район, улица,
  дом, индекс, уточнение (этаж/вход)
- **Контакты:** все телефоны + типы, сайт и все сайты, email, бронирование,
  соцсети (WhatsApp, Telegram, Instagram, VK, …)
- **Классификация:** категория, все рубрики (имена/классы/slug/ID), сеть/бренд
- **Рейтинг:** значение, число оценок, число отзывов
- **Часы работы:** текст, «открыто сейчас», круглосуточно, статус,
  «временно закрыто», часовой пояс
- **Атрибуты:** описание, особенности/удобства (Wi-Fi, оплата картой,
  парковка, …), средний чек
- **Медиа:** количество фото, шаблон URL фото, логотип, панорама
- **Транспорт:** ближайшее метро и остановки с расстоянием
- **Реклама/провенанс:** признак рекламы, ИНН/БИН рекламодателя, награды,
  подтверждённость владельцем, всего найдено по запросу
- **Координаты** и ссылка на карточку Яндекс.Карт

## Режимы сбора данных

### API-перехват (`--api-intercept`) — рекомендуется
Перехватывает XHR-ответы внутреннего API `yandex.kz/maps/api/search` при
скролле. Данные приходят в JSON (`data.items[]`, camelCase) — надёжнее и
**значительно полнее**, чем DOM-парсинг. Поддерживается и публичный формат
GeoJSON (`CompanyMetaData`) как fallback.

### DOM-парсинг (по умолчанию)
Скроллит панель результатов, парсит HTML-сниппеты. Использует устойчивые
селекторы `[class*="..."]` для защиты от обфускации классов Яндексом.
Заполняет базовый набор полей (+ ID/slug/описание из карточки в `--detail`).

## Отчёты и логи (сохраняются автоматически)

При каждом запуске парсер **автоматически** ведёт постоянные отчёты — ничего
включать не нужно:

- `logs/yamap_<дата>.log` — полный лог всего происходящего (уровень DEBUG):
  каждый запрос, скролл, капча, ошибка, пауза троттлинга
- `reports/<время>_<метка>.json` — структурированный отчёт по прогону:
  параметры (домен, вьюпорт, режим, прокси), итоги (всего организаций,
  покрытие каждого поля в %, средний рейтинг, топ-категории), сколько капч
  поймано, длительность, список инцидентов/ошибок, разбивка по категориям
- `reports/<время>_<метка>.md` — тот же отчёт в читаемом виде
- `reports/history.jsonl` — история ВСЕХ запусков, по строке на прогон
  (дата, режим, город, всего собрано, капчи, длительность, ошибки)

Так видно, что и когда собиралось, где Яндекс начал давать капчу и какие
запросы вернули пусто. Папки `logs/` и `reports/` в `.gitignore`.

## Обход анти-фрод системы (SmartCaptcha)

Яндекс.Карты защищены анти-фрод системой, которая детектит автоматизацию.
Парсер противодействует ей без платных сервисов:

- **patchright + настоящий Chrome** (`channel="chrome"`) — нет утечки
  `Runtime.enable` и автоматизационных маркеров, правильный TLS-fingerprint
- **Persistent-профиль** — cookies/localStorage между запусками (Яндекс видит
  «знакомого» пользователя)
- **Консистентный fingerprint под регион** — для yandex.kz локаль `ru-RU` и
  таймзона `Asia/Almaty` (рассинхрон домена и таймзоны палит бота)
- **Прогрев** — естественная навигация `главная → карты` через один домен
- **Человеческая мышь** (кривые Безье), печать по буквам с задержками
- **Адаптивный троттлинг** — замедление при появлении капчи
- **Обработка капчи** — автоклик по SmartCaptcha, ручное решение с
  `--no-headless`
- **Ротация прокси** — `--proxy-file` (для KZ лучше казахстанские
  резидентские/мобильные IP)

## Автодетект селекторов (F12-анализ)

Яндекс периодически меняет CSS-классы. Парсер умеет автоматически обнаруживать
актуальные селекторы через анализ живой страницы: цепочка
**кеш → hardcoded → JS-автодетект**. Найденные селекторы кешируются в
`selectors_cache.json`.

```bash
python yandex_parser.py --detect-selectors --no-headless
python yandex_parser.py --show-selectors
python yandex_parser.py --reset-selectors
```
